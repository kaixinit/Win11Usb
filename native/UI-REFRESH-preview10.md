# preview.10：复制阶段的界面闪烁修正

日期：2026-10-23。本次修改界面刷新机制，保留界面布局与六阶段制作后端。用户截图显示原生版已进入真实 Kingston 57.8 GiB / FAT32 复制阶段；不能据此认定完整复制、最终校验或 UEFI 启动已经通过。

## 原因

原来的每条进度消息均调用 `InvalidateRect(window, nullptr, FALSE)`，使整个父窗口失效。父窗口虽已使用内存位图绘制，但没有 `WS_CLIPCHILDREN`，绘制会涉及日志 EDIT、设备选择器等子控件的区域。日志还按每条消息立即追加并滚动；复制大量小文件时，每个文件又产生完成进度，叠加高频父子窗口重绘。

## 改动

- 主窗口使用 `WS_CLIPCHILDREN`，父窗口绘制排除子控件；保留已有内存位图绘制，最终只复制失效区域。
- 日志和进度经同一个线程安全队列交给 UI，每个待处理批次最多投递一次唤醒消息。后台日志顺序和内容完整保留；尚未显示的进度只保留最新值。
- UI 在约 100 ms 后一次处理批次，进度仅使进度标题、细步骤、进度条和当前文件区域失效。计时器由 UI 调度，不保证忙碌时精确每 100 ms；这不是给制作线程添加等待。
- 日志一次追加一批，追加期间暂停 EDIT 重绘，恢复后一次滚动到最新日志并使该控件重画。滚动在恢复重绘后执行，防止 EDIT 延迟排版时停留在顶部。
- 显示弹窗、打开日志文件、收到制作结束，以及用户确认退出时，立即处理待处理内容。结束消息不会被队列中旧进度覆盖，最终日志写入后才关闭文件。
- 单个过大批次在窗口中保留最新部分，避免超过 EDIT 长度上限导致末尾内容不显示；`session.log` 与会话日志仍保留完整内容。

没有修改 ISO 挂载、设备身份核验、分区、格式化、拆分、文件复制或内容校验实现。

## 验证

`native\test.cmd`：604 项主程序断言和 148 项普通文件 FAT32 工具断言通过，共 752 项；另验证 formatter 无效定位失败和锁定超时零写入。新增队列测试包含单批合并、末次进度、日志顺序、阶段切换与后台/前台并发交接 20,000 条日志。

`native\test-ui.cmd` 直接编译并运行生产 `ui.cpp`，编译时排除写盘后端，使用明确标注的示例设备。测试只在自己新建的 `work/native-ui-tests-*` 写诊断文件和模拟日志，不挂载 ISO，不操作物理磁盘。

| 测试 | 本机结果 |
| --- | --- |
| 单批 5,000 条日志 + 5,000 次复制进度 | 父窗口重画 1 次，日志控件收到 3 次 WM_PAINT；顶部设置区未重画 |
| 单批 5,000 次校验进度 | 父窗口重画 1 次，日志控件和顶部设置区未重画 |
| 失效区域 | 高频复制/校验只涉及进度区域 |
| 日志滚动 | 最新行可见，未停在顶部 |
| 超过 2,100,000 字符的批次 | 控件保持在长度上限内，最新末行仍可见 |
| 结束先于刷新计时器 | 最终日志完整保存，完成状态不被旧进度覆盖 |
| 额外 60 秒动态模拟 | 查看实际窗口，日志持续滚动，进度更新；示例无写盘 |

WM_PAINT 次数是本机这一轮消息测试的结果，不等同于显示器帧数，也不承诺所有 Windows 系统具有完全相同的计数。记录见 [test-results/preview10](test-results/preview10)。

最终 EXE 依赖及 Defender 文件扫描记录与该目录对应；文件扫描不代表目标机动态检测通过。本机动态模拟和失效区域测试不能代替用户在原环境连续复制时的观察。真实大容量 U 盘完整制作、最终校验、弹出、Defender 动态检测及固件启动仍按 [验收表](ACCEPTANCE.md) 继续。

两个最终文件的 CLR RVA/Size 均为零，导入表仅含 Windows 系统 DLL；只读自检、设备枚举、依赖报告均返回 0。对最终文件的完全一致副本进行本机 Defender 文件扫描，返回 0，未检出威胁。
