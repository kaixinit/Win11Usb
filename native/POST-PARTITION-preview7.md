# 新分区建立后的制作流程检查 — preview.7

日期：2026-10-22。保留现有单窗口、六阶段顺序、整盘确认、FAT32/NTFS 选项、4 GiB 拆分规则和结束选择。此次检查沿实际 `NativeBackend` 调用进行，修正后形成独立候选版；GitHub beta.3 与此前验证版不覆盖。

## 检查与修正

| 环节 | 发现的问题 / 原有行为 | preview.7 的处理 |
| --- | --- | --- |
| 新分区 → 新卷 | 刚写入布局便调用严格全量枚举，暂时不完整可能立即停止；仅检查偏移/长度 | 共用等待函数核对原设备、预期 MBR 签名、一个分区、类型/活动标记/编号/范围；卷 GUID 和物理范围连续匹配两次才通过。查询暂缺、卷延迟和缓存空布局可等待，已知身份/新布局冲突立即停止。30 秒轮询期限，有心跳及取消。移除新卷挂载点前重查其卷 GUID |
| FAT32 格式化 | 老工具仍使用 32 位乘法定位，未检查定位返回值；格式化后重复写分区类型；部分查询未核对返回长度 | 使用检查返回值的 64 位 `SetFilePointerEx`；验证 extent / geometry / partition 返回长度、MBR 0x0c 与隐藏扇区偏移。分区类型由主程序建立并核验，helper 只写文件系统元数据，不在结束时重写分区类型；保留部分写入检查、刷新、卸载及解锁 |
| NTFS 格式化 | 向输入管道预先写固定确认字符，依赖系统提示顺序 | 共用参数构造器限定卷 GUID、合法卷标、物理范围与文件系统；`format.com /FS:NTFS /Q /X /Y /V:...`，不再猜测提示顺序。GUI 的整盘确认仍保留，默认取消 |
| 命令结束 → 文件系统 | 命令返回 0 后立即检查，未等待文件系统识别 | 在设备身份复核下，等待读取预期文件系统、有效分配单元和容量；已知错误文件系统立即停止，暂时未识别可有限等待。命令成功不等同于允许复制。设置并复核卷标、核对盘符归属的原有步骤保留 |
| WIM / SWM | 名称连续、大小合规不能证明最后一卷未缺失，也未核对分卷集合 | 保留 DISM `/FileSize:4000 /CheckIntegrity` 和本机 scratch；新增真实 `WIMGetAttributes` 核对每卷的 `TotalParts`、`PartNumber`、集合 GUID，并核对实际大小。ISO 既有 SWM 在清盘前检查，新生成 SWM 在复制前检查；`WIMGetAttributes` 导出在准备阶段提前确认。生成的 SWM 从检查至校验结束持有只读句柄，成功或正常中止时释放 |
| 复制文件集与空间 | 原总量计算只算文件字节及固定余量，未计分配单元舍入；复制/校验函数对相对清单本身检查不足 | 拆分后 WIM 替换与复制/校验共用同一清单；要求 SWM 属于本次 staging，拒绝缺卷、跨任务路径、重复、越界、特殊路径段和文件/目录冲突。按实际分配单元逐文件向上取整并留 64 MiB 余量，溢出检查，复制前重查文件系统、卷标与可用空间 |
| 复制 | 原有 `CopyFileExW`、进度、同名不覆盖、取消均保留 | 全部相对路径在首次写入前验证；每个源文件在复制期间持有只读句柄，拒绝同时改写；源大小/类型或系统复制错误立即停止 |
| 校验 / 完成 | 原来仅检查文件大小，无法发现同样长度的内容损坏；校验无逐文件内容进度 | 复制后先刷新卷缓存，逐文件核对大小并使用 1 MiB 块比较源/目标内容，读不全或内容不同立即停止；显示校验总体/当前文件进度，支持取消。关键启动文件与不残留原 WIM 的检查保留，结束前再次刷新缓存和复核目标设备。所有校验完成后才设置成功标记和进入清理/弹出 |
| 错误文字 | 部分共用目录/组件错误写死“尚未清盘”，但同一函数也可能在清盘后调用 | 共用错误只说明当前失败，是否已经开始重建由真实流程状态决定；更新结束状态为“文件大小和内容校验通过” |

新增文件路径与容量检查复用于准备、复制和校验；没有新增跳过设备核验、自动切换 NTFS、关闭防护或重试格式化的分支。格式化命令失败即停止，等待机制只等待查询/识别就绪，不重复执行格式化。

- FAT32 测试将同一生产 C 源码编入单独测试程序，只允许打开新建 `work/native-formatter-tests-*` 中的普通文件；存储查询、锁卷、卸载 IOCTL 由替身实现。实际调用格式化计算/写入代码处理 8/64 GiB 稀疏文件 × 512/4096 字节扇区，读回核对全容量 BPB、签名、备份引导区、FSInfo、两份 FAT 起始项及空根目录。定位/写入超过 4 GiB 的区域，并确认 32 位回绕位置未变化。结束逐个删除本次普通映像文件，未操作物理磁盘。
- 使用系统真实 WIMGAPI 读取两卷合成 SWM 的编号、总数与 GUID，以及第一卷的索引 1。删除“最后一卷”对应清单项时，即使剩余命名连续也被拒绝。样本仅含项目测试文本，生成说明及哈希见 [fixtures/README.md](tests/fixtures/README.md)，不是 Windows 安装介质。
- 四条成功文件集成路径：FAT32/NTFS × 拆分/不拆分。共用状态机、工作区、实际 WIMGAPI、命令管理、文件复制、逐块内容校验及清理；物理格式化和弹出为替身，DISM 为复制真实两卷样本的测试子进程。
- 十条失败/取消路径：两种文件系统各测试超限 SWM、缺末卷、同大小 EFI 内容损坏、复制取消、校验取消；均不设置成功标记、不弹出 USB、不清理本次 SWM。准备命令失败仍验证在清盘之前退出。

## 仍需实机验收

当前环境没有可清空 USB，进程不是管理员。普通文件中的 FAT32 元数据正确，不能证明某个 USB 控制器支持完整查询/锁卷/卸载，也不能替代真实格式化、系统挂载识别、真实大型安装 WIM 经 DISM 拆分、全盘复制、安全弹出和 UEFI 启动测试。此次新增等待及核验旨在处理明确的中间状态和数据错误，不保证硬件/驱动/空间在整个制作期间始终可用。

内容比较会增加一次源与目标读取，速度受 USB 和源磁盘影响；进度在窗口显示。它比较的是 Windows 文件读取结果，普通缓存读取不代表介质全表面/坏块测试，也不能保证拔出后或日后数据不会变化。空间预检考虑文件分配与余量，不是对任意第三方同时写入或极端元数据增长的保证。

目标机请改用 preview.7，在已备份、明确允许清空的测试 U 盘复测；保留 `session.log`、格式化及 DISM 日志。若失败，以新日志的实际阶段/系统错误定位，不只根据概括提示放宽条件。未通过前保持 GitHub beta.3 不变。
