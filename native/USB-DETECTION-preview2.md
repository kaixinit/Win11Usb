# preview.2：USB 识别兼容性修正

用户反馈：preview.1 在精简 Windows 中可以打开，但刷新后找不到 U 盘。目标电脑尚未提供设备查询日志，因此不能把某一个代码问题断定为该电脑的唯一原因。

已修正：

- 组合框高度原先只有 56px，而 Windows 的这个高度包含展开列表，导致列表几乎没有可用空间；改为预留 360px，折叠栏高度仍为原尺寸。已用两个示例条目实测展开和切换。
- 只读列表此前仅显示“允许制作”的设备，属性/权限/容量等检查不通过就会隐藏。现在只读模式显示已确认属于 USB 的所有设备，并给出缺失信息、未确认项和禁止制作原因。制作模式仍然拒绝状态不完整的设备。
- 按可变长度结构的有效头部长度读取 STORAGE_DEVICE_DESCRIPTOR 和 DISK_GEOMETRY_EX，兼容不返回末尾占位字节/填充的驱动。补充最小长度、截断数据、负容量和 4Kn 测试。
- USB 识别除了存储总线类型，还核对本机 PnP 父设备链，支持经 SCSI/UASP/其他桥接报告的真实 USB 设备。不能只凭型号中有“USB”或遇到根 USB Hub 就允许写盘。
- 分别记录设备描述符、物理磁盘编号、容量、属性和分区布局的查询结果；一个查询失败不再导致整支 USB 从只读列表消失。未知容量/分区数显示为“未确认”，不伪装成 0。
- 部分驱动若要求读权限，尝试 GENERIC_READ 查询句柄；不请求写权限、不自动提权。权限仍不足时保留设备信息和错误码。
- 卷/启动映射失败不再阻断硬件枚举，但会阻止写盘。新增“导出诊断”按钮，列表为空也能保存报告，无需 PowerShell。

验证：186 项自动断言通过，包含原有 164 项以及 USB 父设备链、可变长度头部、部分查询失败的安全边界和诊断隐私检查。本机实际扫描成功，但当前仅能看到一个 Msft Virtual Disk（非 USB）；没有把它误当作 U 盘。真实目标 U 盘的复测仍待用户反馈。

建议先运行 `Win11Usb-NativeReadOnly-v0.2.0-preview.2.exe`。若刷新后仍为空或显示“未确认”，点击“导出诊断”将 `Win11Usb-DeviceReport.txt` 保存到本机，再提供给维护者。报告不自动上传，也不导出原始序列号、PnP 实例 ID 或 ISO 内容。

`--preview-blocked` 仅用于演示“部分查询失败 + 正常设备”两个条目，数据明确标注为示例，不代表真实硬件测试。完整制作候选版仍未通过实盘/UEFI 验收，GitHub beta.3 保持不变。

## 最终构建验证（2026-10-22）

- 自动测试结果：`PASS 186 assertions; no physical disks written`。
- GUI：用两个明确标注的示例设备验证下拉展开、切换选中项，并通过系统保存对话框实际导出 UTF-8 诊断文件；关闭测试窗口后进程退出。未操作真实 USB。
- 实际本机只读枚举退出码 0：1 个磁盘接口、1 个非 USB、0 个查询失败；启动卷映射已确认。主机只有虚拟磁盘，无法据此确认用户电脑上的 USB 已修复。
- 最终两个 EXE 均为 x64 PE，CLR 数据目录 RVA/Size 为 0，静态导入仅含 Windows 系统 DLL，未导入额外的 CLR 或 C++ 运行库 DLL。
- Defender 对最终两个 EXE 的自定义文件扫描退出码 0，报告 `found no threats`。这是本机文件扫描，目标电脑和完整制作过程的动态检测尚待验证。未禁用防护或设置排除项。
