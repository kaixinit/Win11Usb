# 使用与常见问题

本页以原生预发布版 `v0.2.0-preview.14` 为准；[beta.3](https://github.com/kaixinit/Win11Usb/releases/tag/v0.1.0-beta.3) 保留独立下载与 [历史验证记录](VALIDATION.md)。

## 新原生版会覆盖 beta.3 吗？

不会。原生版使用独立标签、版本文件名和发布附件，beta.3 的标签与附件保留。两个 EXE 可以放在不同文件夹，或保持各自版本文件名并存。只有手动用相同文件名复制到相同路径时，才会替换本地文件。新旧程序都直接操作所选物理磁盘，开始前仍须核对写入目标。

## 真的不需要 .NET 和 PowerShell 吗？

原生版的窗口和制作后端均为 C++ / Win32，不使用 .NET、WPF、PowerShell、WMI/CIM，不需要额外安装 VC++ Redistributable。beta.3 是另一条历史实现：C# / WPF 界面和制作阶段的 PowerShell 后端仍需要其原有系统运行环境。

原生版仍使用 Windows 自带的 Win32/GDI+、存储接口、VirtDisk 与 WIMGAPI；大 WIM 拆分需要 DISM，NTFS 需要系统格式化工具。“去掉 .NET”不等于任意精简系统或 WinPE 都保留了完整制作所需组件。缺少所选流程必需组件时应在清盘前报错。

## 单文件免安装，是完全不产生临时文件吗？

分发和启动只需要一个 EXE，无需安装，也无需联网下载依赖。制作时仍会创建任务日志、临时 SWM，并释放独立 FAT32 工具及其源码和许可证。ZIP 是同一程序与说明、许可文件的归档，源码 ZIP 用于查看和构建源码；普通用户直接下载版本命名的 EXE 即可。

## 一支 U 盘为什么显示多个盘符？

PE 或维护工具可能建立数据分区、EFI 或隐藏分区。此工具选择的是整支物理磁盘，确认后清除旧布局并建立一个占用可用容量的分区。

## 大于 32 GB 的 U 盘能选择 FAT32 吗？

可以。原生版通过随程序提供的独立 x64 FAT32 工具格式化，之后核验文件系统、容量、盘符和卷标。目标是建立一个使用整盘可用容量的分区，保留正常对齐开销，不把大盘缩成约 32 GB。已有一次 Kingston 57.8 GiB 整盘、格式化后约 57.7 GiB 可用的实机日志；更多容量和设备仍需验证。当前允许的目标范围为 8 GiB–2 TiB，512/4096 字节逻辑扇区。

原来是 NTFS、或含多个分区的 U 盘也可重新制作，但这不是无损文件系统转换：确认后会删除整支物理磁盘的全部分区和文件。请先备份。

## NTFS 提示“部分 UEFI 固件可能不支持启动”是什么意思？

NTFS 格式化成功不代表所有电脑都能从它启动。本程序不额外安装 NTFS UEFI 驱动，也不建立第二个 FAT 引导分区。无法确认目标电脑支持时，应优先选择 FAT32。

## 7.48 GiB 为什么可能拆成两个或三个文件？

文件系统阈值和 DISM 分卷参数是不同概念。本流程判断阈值为 4,294,967,295 字节，DISM 分卷参数为 4000 MB，输出分卷数量取决于实际映像内容，不按源大小简单向上取整。拆分后会检查每个 SWM 大小，全部放在 sources 中。

## 校验具体检查什么？

原生版先刷新缓存，再逐文件检查大小并逐块读回比较源文件与 U 盘文件内容，拆分场景比较本次生成的 SWM，同时检查关键 x64 UEFI 启动文件。校验过程显示进度并支持取消。

这里没有为每个文件生成一份 SHA-256 清单，也不属于介质坏块或寿命检测；最终能否启动和安装仍需要目标机器实测。beta.3 的历史复制检查以文件大小为主，不能将新版内容校验结论套到旧版上。

## 安全弹出被拒绝就是制作失败吗？

不是同一件事。复制校验通过后，弹出仍可能因占用、驱动能力、权限或设备拓扑限制被拒绝。原生版会分别显示制作和弹出结果，只向核验过的独立存储节点请求移除，不扩大到 USB 集线器、控制器或包含其他磁盘的父节点。只有系统接受移除请求后才提示可拔下。

preview.14 已修正先前的 USB 设备类别识别错误，一次 Kingston 实机日志确认 USB 与 ISO 均弹出成功；这不代表所有设备都支持相同请求。若仍失败，请保留具体错误、通过现有系统菜单导出设备诊断，并使用 Windows“安全删除硬件”。只为取得诊断无需重新制作。ISO 弹出和 USB 安全弹出是独立操作，不能相互证明。

## 强制结束后如何处理？

退出不能回滚清盘、格式化或复制。U 盘可能需要重新制作。本程序挂载的 ISO 也可能保留，请在资源管理器中弹出。不要在制作同时运行其他格式化工具；Windows 的“使用前需要格式化”提示应取消。

## 日志在哪里？

正常结束或失败后，窗口底部会显示 `session.log` 路径；原生版的每次任务目录位于本地应用数据目录，名称以 `Win11Usb-Native-` 开头，DISM、格式化等日志也保存在该目录。窗口系统菜单提供“导出设备诊断…”，包含只读设备和弹出规划信息，不会为导出诊断执行清盘或弹出。

强制终止可能来不及写完最后的会话日志。反馈前请删去个人路径、序列号和不必要的 ISO 文件名；同时附上 EXE 的版本、SHA-256 和具体失败步骤。完整路径不要直接粘贴到公开问题中。

## 为什么未签名，或被安全软件提示？

当前候选版没有代码签名。未签名提示与恶意行为检测不是一回事。出现检测应停止运行、保留检测名称和 SHA-256，通过 Microsoft 官方提交渠道复核，不要关闭防护或添加排除项。单次扫描无检测不代表所有机器都会得到相同结论。
